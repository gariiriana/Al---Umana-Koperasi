# Toksan (Toko Santri) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Role `toksan` with Input Harian, Obral, Produk, Rekap (PDF/DOCX) and Trafik Produk pages, backed by a new Worker + D1.

**Architecture:** New Cloudflare Worker `workers/toksan` (route `koperasi-alumana.com/api/toksan/*`, D1 `toksan`) modelled on `workers/absensi`: Firebase ID token verified in the Worker, role read from Firestore `users/{uid}` via REST (cached 5 min). Frontend pages live in `frontend/src/toksan/` and mount in the existing admin shell; exports are generated in the browser with jsPDF/autotable and docx.

**Tech Stack:** Cloudflare Workers + D1, wrangler 4.150.0, node:test; React 18 + TS, Tailwind 4, lucide-react, jspdf 4 + jspdf-autotable 5, docx 9, vitest.

**Spec:** `docs/superpowers/specs/2026-11-14-toksan-design.md`

## Global Constraints

- Role id `toksan`, label "Admin Toksan". Allowed roles for every API route and page: `toksan`, `super_admin`, `developer`.
- Zero Firestore data access from the frontend for Toksan; the Worker reads only `users/{uid}` (role + name).
- Enum values (DB + API): dapur `bakery|hangat_saji|depan` (labels Bakery, Hangat Saji, Depan); kategori `makanan|minuman|lainnya`; sesi `pagi|siang|sore` (labels Pagi, Siang, Sore); pihak `rijal|nisaa` (labels Rijal, Nisaa).
- Dates are `YYYY-MM-DD` in WIB (Asia/Jakarta). Weeks Senin–Minggu. No date after today WIB.
- Money is integer rupiah, formatted `Rp12.450.000` (id-ID grouping).
- Sales rows snapshot `product_name`, `dapur`, `harga` at insert; updates never refresh the snapshot.
- UNIQUE (tanggal, product_id, sesi, pihak) on sales.
- Export header text exactly: `YAYASAN LEMBAGA WAKAF AL UMANAA`, then `TOKO SANTRI — Rekap Penjualan Harian|Mingguan|Bulanan`, then `Periode: …`; logo `/logo_alumana.png`; footer `Sukabumi, <tanggal panjang>` / `Admin Toksan` / name.
- Migration SQL comments must not contain `;` (the test helper splits on `;`).
- No commits to `main`; work on branch `feat/toksan` in a worktree. Do not deploy.

## Review Focus

1. Retur greater than jumlah, negative or non-integer numbers, empty jumlah → rejected with the row index, nothing saved (Task 3 test `rejects retur > jumlah and names the row`).
2. Same product + sesi + pihak added twice on one date (in one batch, or against an existing row) → 409 `DUPLIKAT` naming the row; UI focuses the existing row instead (Task 3 test, Task 8 test `addProduct focuses existing duplicate`).
3. Price changed in Produk after sales were saved → past rows and recaps keep the old harga; a period containing both prices shows two lines (Task 3 test `price change does not rewrite saved rows`, Task 5 test `groups by product and harga`).
4. Week/month boundaries around WIB midnight and weeks crossing a month (e.g. Mon 27 Oct – Sun 2 Nov 2026) → correct ranges (Task 8 tests on `weekRange`/`monthRange`).
5. Leaving the Input page with unsaved edits, or saving with a row missing sesi/pihak → save blocked and missing chips highlighted; browser `beforeunload` warning while dirty (Task 8 test `validateRows flags missing sesi and pihak`, Task 9 manual check).

  ```

    produk: [{productId, productName, dapur, harga, produksi, terjual, retur, omzet}],
  ```
